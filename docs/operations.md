# Ramp 小团队试用运维手册

更新：2026-09-10。适用部署：单机 Docker Compose + MariaDB，仅管理 `/opt/ramp`、`ramp` 和 `ramp-mysql`。同机 kaogong 及其 80/8770 端口不在操作范围。

## 页面和健康状态

- 普通成员在「工单与试用」查看自己的申请/指定给自己的审批及反馈；新人还可以查本人的操作记录。
- 运营/管理员在同页查看近七天请求统计、反馈和脱敏审计。没有数据时显示零，不生成演示成绩。
- `/health/live` 表示进程可响应；`/health/ready` 检查数据库及必要迁移，异常返回 503。两者不调用付费模型。
- 详细 `/api/health`、`/api/ops/readiness` 需要登录并满足角色限制；配置了密钥不等于真实模型服务已验证可用。

## 发布步骤

1. 本地执行 `python -m unittest discover -s tests -v`、`python scripts/check_web.py`、编译检查；审查改动、检查密钥和私有数据，提交后用 `git archive` 打包该提交。不要打包整个工作目录。
2. 上传 `deploy/backup.sh`、`deploy/verify-backup.sh`、`deploy/prepare-release.sh` 后，先运行 `bash /opt/ramp/deploy/prepare-release.sh`。该脚本保存旧镜像标签、代码配置包、审核报告与数据库，随后把备份恢复到随机隔离数据库检验，最后只删除该临时库。输出必须成功才可继续。
3. 将发布归档解压到 `/opt/ramp`。部署文件 `.env` 不在归档内，不覆盖。既有审核文件保存在 `/opt/ramp/runtime/reports`，应用通过挂载读取。
4. 如仍使用数据库 root，运营人员用 root 配置单次运行 `scripts/provision_db_user.py`，将随机数据库账号保存到部署 `.env`。应用只获得 ramp 库读写与迁移必需权限，无全局管理、授权或 DROP 权限。不要输出 `.env` 或完整 Compose 展开配置。
5. 在 `/opt/ramp/deploy`，用提交 SHA 设置 `RAMP_RELEASE`，用唯一标签设置 `RAMP_IMAGE`；执行 `docker compose config --quiet` 和 `docker compose build app`。构建后用 `scripts/set_release.py` 将完整 SHA 和对应镜像标签原子写入部署 `.env`，防止下次 Compose 操作误用旧的 latest 镜像；该脚本不打印其他环境变量。
6. 用相同环境执行 `docker compose run --rm --no-deps app python -m ramp.migrate_knowledge`，再 `docker compose up -d --no-deps app`。不执行 compose down、不删除卷、不重置账号、不装载演示人员。启动会重复执行安全的增量迁移。
7. 检查容器健康、公开存活/就绪、未登录访问受限接口、登录后的版本号以及原网站仍正常。可在应用容器运行 `python -m scripts.verify_release`，使用运营人员提供的管理员凭据验证；默认值仅适用于已有演示账号，不会修改密码。保存实际发布 SHA、备份路径和结果。

依赖以 `uv.lock` 导出的 `deploy/requirements.txt` 固定，升级应重新导出并回归。GitHub Actions 会运行不依赖真实数据库/模型的测试，但没有自动云端部署密钥。

## 日常备份与恢复

运行 `bash /opt/ramp/deploy/backup.sh`：在同机 `/opt/ramp/backups` 写入 gzip SQL 和 SHA256 校验文件；目录仅限运维访问。运行 `bash /opt/ramp/deploy/verify-backup.sh /opt/ramp/backups/实际文件.sql.gz` 做隔离恢复验证。备份包含私密会话和账号哈希，不能放 GitHub 或面试打包件。

本轮不创建无人负责的自动备份/通知承诺。小团队试用期间由组织者指定运维人员每日备份、检查空间，并迁移到加密异地存储；保留周期需确认，脚本不自动删除历史备份。日志按 10 MB × 3 轮转，不代替完整监控。

回滚先停止新写入并确认兼容性。知识版本上线后不能直接运行“不理解草稿/版本”的旧应用，否则可能把草稿当制度检索。优先前滚修复；若必须退回旧代码，应在隔离环境恢复匹配备份验证，并由组织者明确接受备份时间点后的数据损失，再安排正式恢复。本手册不提供一键覆盖生产库的快捷命令。

## 中断和异常怎么处理

| 情况 | 处理 |
|---|---|
| 提问页面断网 | 先查操作记录或“查询/恢复上次请求”，使用原请求编号；不要连续新发付费问题。 |
| 已完成但客户端没收到 | 原编号返回已保存的结果，不重新调用模型。 |
| 问答运行中进程中断 | 标记/提示结果不确定；不保证从任意模型步骤续跑，核查后可以新会话。 |
| 确认工单时中断 | 使用原 action_id 查询/恢复；同一操作编号与工单在一笔事务中保存，重复不会新增同单。 |
| 参数、审批人或资源配置变更 | 拒绝旧确认，核查是否已存在待处理单，再重新发起；不能自动接受新审批配置。 |
| 工单待审批但无审批人 | 管理员补资源负责人；申请人取消原待审批单后重提。不会冒充已自动分派。 |
| 单个用户同时提交 | 返回 409，等待并查结果。 |
| 容量/问答日限额 | 默认最多 3 个执行、每账号每天 50 次问答，429 时按提示处理；不是精确费用预算。 |
| 真实外部系统超时 | 当前尚未接入。未来必须增加下游幂等与状态对账，不能沿用“本地事务成功”当作外部成功。 |

## 试用和权限约束

禁止在生产数据上运行 reset、wipe、演示装载、破坏性检查脚本。真实 MySQL 验证脚本 `scripts/verify_mysql_controls.py` 需要运维权限，只在自己创建的随机隔离数据库做测试，最后删除该库；不得给应用账号提升全局权限来运行它。

线上默认关闭 `RAMP_ALLOW_DEMO_LOAD`。注册用户由管理员设置角色和入职资料；不允许用户通过注册接口自授管理员身份。审批必须指定账号且不能自审；管理员仅有配置权限不等于业务代审批权限。

当前公网 HTTP、默认演示凭据、过期宿主系统、同机备份、单进程限流等风险见企业就绪评估。在完成加密传输和账号治理前，只使用演示数据。
