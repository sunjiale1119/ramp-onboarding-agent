# 企业就绪评估与团队试用方案

更新：2026-09-10。结论：具备受控小团队试用的工程基础，不能认定为正式企业生产系统。

## 本次已实现什么

| 能力 | 当前交付 | 不能据此声称 |
|---|---|---|
| 知识治理 | 草稿、人工发布、版本差异、主题/适用范围冲突阻断、日期生效、历史查询、撤回与恢复审计 | 能自动发现所有语义矛盾；已与真实 HR 规则引擎同步 |
| 操作可靠性 | 用户级数据库锁、请求回执、载荷一致性校验、工单与回执同事务、重复确认返回同单、确认前重校配置 | 所有外部 API 都能 exactly-once；模型运行中断都能无成本续跑 |
| 权限 | 登录、角色、会话本人、当前 Mentor 关系、指定审批人；管理员也不能代审批或查看新人个人记忆；禁用/角色变更撤销会话 | 多租户隔离、企业 SSO/MFA、全面渗透测试已经完成 |
| 运维 | 不消耗模型的存活/就绪检查、有限日志、脱敏操作审计、数据库备份与隔离恢复脚本、限额/并发限制、依赖锁定、CI 检查 | 高可用、异地灾备、自动告警和 24 小时值守已经完成 |
| 团队试用 | 真实账号、反馈收集与处理、近七天参与账号和请求状态统计、操作查询页面 | 已完成企业试点、已有活跃人数或满意度提升证据 |

“我的信息查询”来自 HR/管理员确认或企业网关推送的最新快照，包含来源、记录人、日期和有效期；缺失、过期或撤销必须说明无法判断，不回退旧版。工单增加指派、办理凭证、失败重分配及本人验收；实际开通仍由 IT 在企业系统执行。知识内容为演示制度，不能当作真实用工依据。

空环境已支持可视化建立资源、材料和岗位范围，不再要求管理员手工调用接口。入站数据接口要求 HTTPS、哈希令牌、字段范围及版本号；接口管理字段不允许人工覆盖。详见[使用说明](user-guide.md)与[企业接入契约](enterprise-integration.md)。

## 验证证据与范围

- 72 项自动化用例：24 项知识版本 + 36 项服务控制 + 12 项企业业务，临时 SQLite 隔离，未使用真实账号或付费模型。
- 另有真实 MySQL 隔离库测试：并发互斥、锁释放、持久化暂停、重新创建图和 saver 后恢复、单工单回放。不是模拟断电、网络分区或全机灾难演练。
- 前端静态检查覆盖 API 路径与脚本解析；桌面浏览器验证新增页面空状态。不是全设备无障碍认证或完整浏览器端到端覆盖。
- 最近留存的模型黄金集仍为 README 的 58/60，本轮未重新运行付费模型评测。新增工程测试通过率不能替代答案质量。
- 发布备份、恢复演练、云端健康验证结果由本次交付记录确认；有脚本不等于所有环境已执行。

## 删减和纠正

删除 HR 按个人读取记忆的多余接口；去掉未执行的工具超时字段和并发不安全的工单递增编号；移除自动分派、自动通知、五分钟撤回和自动回收等未实现承诺。真实 API 的 live 模式现在明确报未实现，不再落入演示逻辑。线上禁用一键生成演示账号，保留知识、RAG、领域路由和 Mentor 协作，因为这些与核心业务有关。

当前 HR/IT/业务是受控领域子图，不包装成互相自主协商的“全自动 Agent 团队”。现有模块不因数量多就有价值，也不为了简历覆盖知识点继续增加框架。

## 正式企业上线前的阻断项

1. 公网 HTTP 演示入口不能承载真实敏感员工数据：先配置域名与 TLS、可信反向代理，验证 Cookie/Origin，再关闭默认演示凭据并采用企业身份管理；目前不具备这些条件。
2. 更换已停止维护的宿主操作系统，完成依赖漏洞扫描、独立权限/渗透审查；容器不是宿主安全补丁的替代品。
3. 接真实 HR/工单/权限 API 时，必须实现下游幂等键、状态查询与对账；没有幂等能力的写接口遇到超时应转人工，不盲目重试。
4. 已移除硬编码个人状态推算，但企业仍需指定数据负责人、源系统更新频率和争议处理规则。当前入站接口是单网关凭据，未实现源事件乱序阻断；IT 执行复用 ops 角色，严格分岗要求尚需拆分。模型数据传输范围须经企业审批。
5. 当前单机单进程，没有自动故障切换；备份同机保存不等于灾备。补异地加密备份、恢复目标、自动告警和值班责任。
6. 知识冲突检测只对已结构化的主题、范围、时间强约束；近似文本提示可能漏检，仍需要制度负责人审核。
7. 补真实试点、压力测试和隐私留存/删除策略。当前请求数量限额不是精确人民币预算；IP 登录限流为单进程内存态，不能当作分布式风控。
8. 审计为应用数据库记录，未接不可篡改存储；备份含会话和账号哈希，必须严格限制访问。管理员业务权限受限不意味着服务器 root 无法读库。

## 建议试用：5–10 人、7 天（计划，尚未实施）

只用非敏感试用身份和演示制度。组织者创建/审核真实试用账号，分配至少一位 Mentor、一位审批人；不生成“完成试用”的虚构用户。

第一天确认入职日期、带教关系、岗位资源与审批账号。第二至五天每人体验制度问答、追问、缺数据查询、权限确认、取消/批准/驳回、知识更新后再次提问，并在「工单与试用」提交真实反馈。运营每日记录无法完成的任务并标记处理结果。最后两天复测修复并由组织者汇总。

停止条件：任意越权泄漏、重复创建同一确认工单、未确认发生写入，立即停止受影响功能。回答质量单独人工抽查，记录分母与具体错误，不以“接口返回成功”代替“答案正确”。

建议观察：真实参与账号、场景任务完成率、人工核实的回答正确性、升级 Mentor 原因、P50/P95 等待时长、每次真实任务费用、反馈闭环时间。本轮只实现请求状态与反馈统计，延迟分位数和完整业务质量报表仍需汇总分析；指标目标应在试点前由组织者确认，不能把目标写成结果。
