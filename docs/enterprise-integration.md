# 企业落地与数据接入契约

更新：2026-09-10。当前实现为“一家企业一套实例、独立数据库”的员工服务工作台，不是多租户 SaaS，也不替换企业 HR、身份或权限系统。

## 1. 产品落地路径

先让知识问答和人工办理闭环可用，再接企业已有系统的数据。没有接口时不是伪造 HR 系统：HR 对已核实数据负责，IT 在原系统办理并登记凭证，新人验收。这个模式需要有人值守和更新，不应包装成全自动。

| 阶段 | 企业需要提供 | Ramp 当前能力 | 放行依据 |
|---|---|---|---|
| 需求确认 | 制度负责人、HR 数据负责人、IT 办理人、试点群体、事项范围 | 角色、服务目录、知识治理、人工流程 | 责任人和禁止处理的数据明确 |
| 安全部署 | 内网/受控网络、域名证书、受维护服务器、备份与安全负责人 | 单实例部署、账号会话与权限、健康及恢复脚本 | 加密传输、身份核验、恢复及安全审查通过 |
| 人工试点 | 已核实制度、有限数据、实际审批及执行账号 | 来源快照、人工审批/交付/验收、反馈 | 场景任务由真实参与者完成，缺数据不编造 |
| 只读数据集成 | 企业网关、来源接口权限、员工标识映射、字段授权 | HTTPS 入站快照接口、字段范围、版本校验 | 双边对账、停同步后过期拒用、撤销验证 |
| 自动办理扩展 | 企业写接口、幂等及查询能力、失败处理人 | 尚未实现，不由本轮模拟 | 下游重复提交、超时和对账验收后才开放 |

当前没有企业专属接口地址或授权，因此仅实现 Ramp 侧接入契约，没有声称已接通飞书、钉钉、SAP、企业微信或任一真实 HR/IT 平台。

## 2. 身份和数据边界

- 每家公司独立实例、数据库、凭据和备份。当前没有租户 ID 隔离，不能把多家公司混放后声称多租户安全。
- 当前身份入口为本地注册、管理员核验激活。注册不能证明员工身份，管理员须依据企业名单核验。已有会话在停用或角色变化后撤销。
- 企业 SSO/OIDC/SAML 和自动离职同步尚未实现；实际对接必须拿到企业 IdP 信息后完成签名、受众、回调、绑定及停用测试。不能直接信任客户端传来的身份或任意代理身份头。
- 企业网关维护不可随意复用的员工标识到 Ramp `username` 的映射；入站同步只能写已存在且激活的账号，不能创建员工、赋予管理员或变更 Mentor。
- HR 可维护 HR 快照，管理员可维护权限快照；新人通过本人绑定的工具查询。质量运营与 IT 执行目前共用 ops 角色，正式分岗要求需另行拆分。
- 知识片段、对话、工具结果会用于模型推理，可能传输到配置的模型服务。正式员工数据接入前必须由企业批准模型供应商与传输范围，必要时改用企业批准的模型部署并回归，不能因数据库在内网就声称数据全部留在内网。

## 3. 入站同步：企业网关主动推送

企业侧从获授权的 HR/IT 来源读取最小必要字段，映射员工，再向 Ramp 推送快照。Ramp 不接受任意来源 URL，不替企业存储 HR 系统管理员密码，不主动扫描内网。

### 部署配置

由运维在安全的凭据管理渠道生成至少 32 字节随机令牌。企业网关持有令牌，Ramp 仅配置其 SHA-256 十六进制摘要，不把明文令牌写到 README、代码、聊天或日志。

```dotenv
RAMP_DATA_INGEST_TOKEN_SHA256=<令牌的64位SHA256十六进制摘要>
RAMP_DATA_INGEST_FIELDS=probation,leave_balance,social_insurance,housing_fund,onboarding_docs
RAMP_EXTERNAL_MODE=builtin
```

这是快照推送模式，仍使用 `builtin` 查询存储记录；不要设为未实现的 `live`。需要同步权限时由运维明确授权 `entitlements`，默认不允许。

一套部署目前只有一个网关凭据及一组字段权限，不支持每个源单独凭据、密钥版本或自动轮换。建议企业统一数据网关接入，拆分数据源凭据治理仍是后续能力。

配置了凭据与字段后，这些字段归接口管理，人工保存或撤销会返回 409。切换归属先暂停同步、核对末次版本，再变更配置并重启；不能人工和接口竞争最后写入。轮换时同步替换双方凭据，旧令牌立即失效，需安排切换窗口。

### 网络要求

应用只接受 HTTPS 语义的入站请求。反向代理必须覆盖客户端的转发头；应用仅信任实际代理地址，不得配置任意来源都可信；应用端口不得绕过代理暴露给不可信网络。还需在企业网关实施来源限制、速率限制、请求超时及失败告警。

当前公网 `http://8.148.245.200:8000` 不能用来推送真实数据。TLS、可信代理与网络规则属于企业部署验收项，现有 Compose 不是一份完整的企业网络安全配置。

### 第一步：读取当前版本

```http
GET /api/enterprise/ingest/revision?employee_id=<已有员工账号>&field=leave_balance
Authorization: Bearer <网关令牌>
```

响应仅包含 `{"revision": 0}` 或最新版本号，不返回个人字段内容。读取版本也需要 HTTPS、同一凭据和字段权限。

### 第二步：提交来源记录

```http
POST /api/enterprise/ingest
Authorization: Bearer <网关令牌>
Content-Type: application/json
```

以下是接口格式示例，不是实际员工数据；账号、日期和来源需换成企业真实核实结果：

```json
{
  "employee_id": "<已有员工账号>",
  "field": "leave_balance",
  "value": {"total": 5, "used": 1},
  "as_of": "2026-09-10",
  "valid_until": "2026-09-17",
  "source_ref": "<源系统记录编号>",
  "expected_revision": 0,
  "revoked": false
}
```

成功返回新版本、来源类型、记录人、数据和有效期。企业网关应记录成功回执并与源系统对账，不仅看网络请求有没有发出。全量请求体受 128 KB 限制；当前每次只写一个员工的一个字段，不提供批量导入事务。

| field | value 允许内容 |
|---|---|
| probation | `probation_end`：ISO 日期，仅合同结束日，不是通过转正 |
| leave_balance | `total`、`used`：0–366 的有限数字，已休不超过总额；剩余额度由两者相减 |
| social_insurance | `status`：paid / pending / not_started / unknown；可选 `actual_from` 日期 |
| housing_fund | 同上状态；可选 `base`：非负整数基数，最多 10000000 |
| onboarding_docs | `submitted`：已配置材料标识数组 |
| entitlements | `granted`：已配置资源标识数组，默认没有接口授权 |

不存在的字段、额外角色参数和未知目录项均拒绝。快照日不得在未来；有效期须覆盖今天且不超过快照日后 90 天。更新频率由数据负责人决定，90 天是上限而不是建议频率。

撤销时使用相同员工和字段、当前版本号、`revoked:true`、`value:{}` 及来源说明；追加撤销版本，不删除历史。最新记录过期或撤销后不会回退到旧版。

### 重试与故障

| 响应 | 网关应如何处理 |
|---|---|
| 200 | 保存回执。完全相同的请求再次提交且其仍是最新版本时返回原版本，不重复追加 |
| 400 / 422 | 修正身份、字段值、日期或请求格式；不要无限重试 |
| 401 | 核对凭据，禁止把令牌写入报错日志 |
| 403 | 字段未授权，交由负责人确认，不自行扩权 |
| 409 | 当前版本变化；重新读版本并与来源核对，不直接用新版本号覆盖可能更新的数据 |
| 503 / 网络超时 | 保存原请求并有限重试同一内容；若最新版本已变化，转对账；同时检查健康与告警 |

这里只保证本地记录的版本校验与同请求回放，不是企业所有系统的分布式 exactly-once。网关必须串行处理同一员工同一字段，识别源端事件顺序，不能把晚到的旧事件当新事实推送。当前尚未提供源事件序号/时间级别的乱序阻断。

## 4. 对外执行为什么先保留人工

当前工单提供申请、审批、指派、办理结果、凭证、失败重分配、本人验收或退回。只有指定执行人能登记完成，且申请人不得执行自己申请。Ramp 不保存企业资源的开通密钥，不假装点击批准就开通。

未来接自动写接口时，先为每个操作实现下游幂等键、状态查询、超时对账、失败人工接管与回收责任，再考虑自动重试。仅有 LangGraph 暂停恢复和本地事务不够。到期权限回收、消息通知、企业审批同步尚未实现。

## 5. 正式上线验收清单

企业业务、安全、IT 三方共同确认，不由开发者自己宣布“企业级认证”：

- 制度来源与业务数据负责人、适用范围、更新周期和争议处理明确；演示制度已替换或隔离。
- 企业身份核验、离职停用、必要岗位分权、敏感数据与模型传输范围通过审查。
- 受维护宿主、TLS、可信代理、网关来源/速率限制和默认密码治理完成。
- 缺失、过期、撤销、重复推送、版本冲突、无效凭据和越权字段已联调验证。
- 一张工单在真实企业系统实际办完，由员工验收；失败与无人办理有责任人，不依赖不存在的自动通知。
- 备份在异地受控存储，实测恢复；上线容量与响应目标由压测确认，故障有值班与回滚流程。
- 试点指标有真实分母与人工核对结果；数据留存、删除、审计保全及供应商准入方案完成。

当前代码实现了上述部分机制，但未完成真实企业联调、安全验收、规模压测或真实团队试点。详见[就绪评估](enterprise-readiness.md)及[操作说明](user-guide.md)。
