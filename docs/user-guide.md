# Ramp 使用说明：从空环境到一张工单结单

更新：2026-09-10。适用：单企业独立部署、人工办理模式及已配置的业务快照推送。

Ramp 是员工服务入口，不是薪资核算软件，也不是自动开通权限的平台。制度由负责人发布，个人状态由负责人核实或企业接口同步，实际权限由 IT 办理。系统负责把问题、依据、申请、审批、交付和验收串起来。

> 当前公网体验站仍是 HTTP 演示环境，只能使用非敏感试用数据。真实员工信息须等企业完成加密传输、身份及数据安全验收后再录入。不要把身份证、密码、薪资明细或原始凭据附件粘贴到系统中。

## 1. 先分清谁负责什么

| 身份 | 登录后的主要入口 | 实际责任 |
|---|---|---|
| 管理员 | 管理后台；工单与试用 | 激活成员、设置带教关系、建立服务目录、指定审批人、发布知识、维护权限快照、指派办理人 |
| HR | HR 看板；工单与试用 | 核实并维护个人事项记录；查看入职主题聚合，不读取新人个人记忆 |
| Mentor | Mentor 带教；工单与试用 | 处理分配新人的升级问题；提交知识草稿；如被指定，可审批工单 |
| 运营 / 质量 | 运营与质量；工单与试用 | 处理反馈和运行问题；被指派后可担任 IT 执行人 |
| 新人 | 新人工作台；工单与试用 | 提问、核对引用、确认申请、查看进展、验收自己的交付 |

当前 IT 执行人复用“运营 / 质量”角色，也因此拥有相应运行质量页面权限。企业若要求 IT 执行与质量运营严格分岗，须先拆分权限再正式上线，不能仅改角色显示名称。管理员不能代替指定审批人审批，申请人不能自审或执行自己的申请。

## 2. 管理员首次配置（按顺序）

### 第一步：激活实际使用者

1. 参与者打开登录页，选择“注册”，填写自己的账号、姓名和密码。注册后处于待激活状态。
2. 管理员登录“管理后台 → 成员”，点击该账号的“设置”。
3. 填写角色；新人同时填写团队、岗位、入职日期、领域和 Mentor。Mentor 必须先注册并被设为有效 Mentor。
4. 激活账号并保存。账号就是人员标识，不再要求建立另一份“员工档案”。

不要为了演示装载一批虚构人员。离职或停止试用时先停用账号，系统撤销其登录会话；随后核对该人的审批和执行任务，由管理员重新配置或分配，不能放任无人处理。

### 第二步：建立企业服务目录

1. 点击顶部“工单与试用”，找到“企业服务配置”。
2. 类别选“可申请资源目录”，填写稳定标识（如 `vpn`）及显示名称，点击“保存条目”。这里只建立可申请项目，不创建真实 VPN。
3. 类别选“入职材料目录”，登记企业实际要求的材料项目；只保存项目名称和提交状态，不上传证件原件。
4. 类别选“岗位应有权限”，岗位名称与成员设置的岗位一致，勾选所需资源；`*` 表示未匹配岗位的默认范围。明确配置为空清单时不会自动继承默认项。
5. 返回“管理后台 → 外部系统”，为资源选择实际审批账号及预计处理天数（自然日），为 HR/IT 等服务选择实际联系人，保存配置。

缺少审批人、审批人已停用或审批人就是申请人时，申请会被阻止。并行编辑返回“配置已变化”时先刷新核对，不用旧页面覆盖他人修改。被岗位、审批配置或未结工单引用的资源不能直接删除。

### 第三步：审核本企业的制度

进入“管理后台 → 知识库”，建立或导入 TXT/Markdown 条款，填写领域、规则主题、适用团队、生效日期和来源。保存草稿、查看差异及冲突后再发布。草稿不能用于回答；不同制度主题冲突不能只靠“新版优先”解决。

演示知识不能未经核实就作为企业制度上线。具体更新与恢复操作见[知识版本说明](knowledge-versioning.md)。

## 3. HR 怎样录入个人事项

入口：“工单与试用 → 带来源的业务记录”。

1. 选择员工账号，再选择需要确认的事项。
2. 对照自己有权访问的 HR 来源填写数据：合同试用期结束日、核定年假总额与已休天数、社保/公积金状态，或已提交材料。
3. 填写“来源数据截至日期”“此记录有效至”和内部来源编号。编号用于追溯，不应填写密码、证件号码或敏感原文。
4. 勾选已核对身份、来源和权限，点击“确认并保存新版本”。页面显示版本、记录人、来源和有效期。
5. 新人登录自己的工作台提问，例如“截至已确认记录，我的年假还剩多少？” 工具返回记录及来源日期；没有记录时应提示核实，而不是默认零天。

有效期必须覆盖当天，最长为快照日后 90 天；这个上限是系统保鲜限制，不是所有 HR 数据都应保留 90 天。负责人应按业务更新频率设置更短期限。系统不会自动续期，需组织者安排定期核对。

填错后重新核对并保存新版本；不可信时点击“撤销当前记录”并确认。撤销和过期均停止使用最新记录，不能自动恢复旧版。旧版本留存在数据库中；当前页面只展示最新版本，不提供个人记录历史回放界面。

试用期结束日不等于已经通过转正；社保“待办理”必须由负责人确认，缺记录不能等同于待办理。权限快照只能由管理员核实维护，HR 无权修改。

若按钮不可用且该字段属于企业接口管理，应在源系统修正；不能在页面临时覆盖。运维如需切回人工，应先停止同步任务、核对最后版本，再明确调整字段归属，不能两边同时写。

旧版无来源业务数据仍保留供管理员核对，但不再被工具当作个人事实。升级后出现“查不到”时，应补核实记录，不要重新开启旧演示推算。

## 4. 一张权限工单怎样真正办完

1. **新人提出申请**：说明资源、业务理由和所需天数。核对 Agent 的确认卡片，再点击确认。未确认不能创建工单。
2. **指定审批人决定**：进入“工单与试用 → 我的申请与待我审批”，批准或驳回并写说明。新人也能取消仍待审批的申请。
3. **分配办理责任**：审批人或管理员在“登记工单执行与验收”选择已批准工单，选择“指派执行人”，指定有效的运营 / IT 执行账号并填写说明。
4. **IT 真正办理**：指定执行人到企业现有 IT 系统操作，成功后回到 Ramp 登记交付，填写企业工单号或执行凭证编号。失败时选择失败并说明原因，由管理员或审批人重新指派。
5. **新人验收**：申请人检查真实资源能否使用，再选择验收结单；不能用时退回办理。系统保存状态与操作审计，不会只因 IT 写了“完成”就替员工验收。

已批准、办理中、失败待重分配、已交付待验收的同一资源申请都不能重复创建。工单列表显示执行账号、交付凭证和说明；审批通过不等于外部开通，交付凭证也只是责任人的登记，不是 Ramp 自动核验的证据。

交付完成不会自动改写“已开通权限快照”。管理员或企业数据接口还应同步实际权限状态。申请期限只是办理约定，当前没有到期自动回收；IT 必须另行负责到期核查与回收。

## 5. 制度答不出来怎么办

新人检查引用与适用范围；知识不足时系统可升级给其当前 Mentor。Mentor 在带教页面处理，选择沉淀的答案只成为知识草稿，管理员审核发布后才能供后续新人检索。不要把某人的个人办理结果沉淀成通用制度。

没有 Mentor 时，管理员先补带教关系。当前不自动发邮件或企业 IM 通知，试用负责人需要约定审批人、Mentor 和 IT 每日查看待办的时间。

## 6. 常见问题

| 页面提示 / 现象 | 应该怎么处理 |
|---|---|
| 新账号登录不了 | 管理员先激活并设置角色，不是重复注册 |
| 社保、年假或权限查不到 | 负责人核对记录是否存在、在有效期内、未撤销；缺失不表示尚未办理 |
| 记录 / 配置已变化 | 刷新后核对最新内容，再重新编辑，不绕过版本检查 |
| 提交后断网 | 先刷新记录。问答/确认使用原请求编号恢复；交付更新若返回版本冲突，核对最新状态后再决定，不盲目重做外部操作 |
| 已批准但用不了 | 查是否已指派、IT 是否真正办理，不再找 Agent 重复申请 |
| 交付失败 | 写清失败原因，由审批人或管理员重新分配 |
| 接口凭据已配置但查询仍无数据 | 配置不是联通证明；核对企业网关成功回执、员工映射、字段范围与有效期 |
| 认为回答不对 | 在“工单与试用”提交具体反馈，避免敏感原文；运营登记处理结果 |

## 7. 一次可复核的小团队验收

由真实参与者分别完成：空环境配置；一条带来源记录查询；撤销后再次查询；制度新旧版本切换；一张申请批准、指派、实际办理、验收；一张失败退回；跨账号访问被拒绝；一次断网后查结果。记录哪些任务成功、哪里失败及修复情况。

界面截图、工程测试和接口成功都不等于真实业务验收。问答质量须人工核对依据；是否真正开通须在企业系统验证。当前没有已完成企业试点的效果数据。
