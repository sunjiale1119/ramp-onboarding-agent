# 爬坡 Ramp

面向新人入职前 30 天的带教 Agent：回答制度问题、查询个人入职事项、协助提交权限申请，并将无法解决的问题交给 Mentor。可复用的人工回答经过审核后进入知识库，供后续新人使用。

这是一个可运行的 AI 产品作品集，包含产品流程、五类角色页面、Agent 后端、内置业务系统、知识版本管理、自动化测试与云端部署。当前定位为**受控小团队试用版本**，尚未完成真实企业试点或生产安全验收。

[在线体验](http://8.148.245.200:8000/login) · [知识版本说明](docs/knowledge-versioning.md) · [技术选型](docs/adr-001-agent-runtime.md) · [企业就绪评估](docs/enterprise-readiness.md) · [运维手册](docs/operations.md)

文档更新：2026-09-10。功能发布基线为 [`9e45ee3`](https://github.com/sunjiale1119/ramp-onboarding-agent/commit/9e45ee3a30a4a0758eb92f9292b1a890a36a6a38)。后续文档提交不代表应用重新发布。

> 在线站点目前为 HTTP 演示环境。请勿使用常用密码，勿输入身份证、薪资、客户资料等真实敏感信息。新注册账号需要管理员激活；没有数据时，不会自动生成员工或试用成绩。

## 1. 解决什么问题

新人入职时，制度查询、个人事项和操作申请通常分散在不同入口；Mentor 需要重复答疑，制度更新后又容易出现新旧口径混用。Ramp 将这些任务放到同一个对话入口，但不把所有问题都交给模型自由回答。

- 制度问题必须有适用版本和来源，不能用个人经验冒充公司规定。
- “我的社保交了吗”必须查个人记录，不能拿通用规则推断实际缴纳状态。
- “帮我申请 VPN”必须先确认再执行，不能把生成文字当成已经办成。
- 没有足够依据时，应说明缺失或交给 Mentor，而不是补一个听起来合理的答案。

以上是本项目验证的产品假设，不是已证实的企业提效结论。公开语料整理属于探索材料，不等于完成用户访谈；目前没有真实企业节省工时或满意度提升数据。

## 2. 当前已经实现的能力

| 能力 | 用户能做什么 | 关键约束 |
|---|---|---|
| 制度问答与连续追问 | 查询制度、查看引用，继续追问上一轮问题 | 按领域、日期和团队过滤知识；聊天历史不替代制度依据 |
| 个人入职事项 | 查询已录入的社保、公积金、材料、Mentor 和权限信息 | 缺少数据时明确说明；演示推算不代表真实人事结论 |
| 权限申请与审批 | 查看确认卡片、提交申请、批准/驳回、取消待审批申请 | 仅指定审批人可审批，不能自审；重复确认返回同一工单 |
| 知识版本管理 | 草稿、差异、冲突审核、定日生效、历史查询、恢复旧内容 | 草稿不进入回答；已发布内容不原地覆盖；恢复也要重新审核 |
| Mentor 带教 | 查看分配新人的主题信号、处理升级卡片、提交可复用回答 | 服务端验证当前带教关系；回答先成为知识草稿 |
| 入职时间线与记忆 | 查看 30 天节点、保留对话上下文、读取或删除自己的可见记忆 | 个人记忆与他人可见的主题信号分开处理 |
| 操作查询与恢复 | 断网后查询已保存结果、恢复待确认操作、转到新会话 | 不盲目重跑结果不确定的付费问答；新会话不等于取消旧工单 |
| 运维与团队试用 | 提交反馈、查看处理结果、请求统计和健康状态 | 数字来自实际记录；请求完成率不等于回答正确率 |

当前没有自动通知、自动开通或回收企业权限，也没有“点击确认后五分钟内自动撤回”的承诺。工单批准仅改变本项目里的记录。

## 3. 谁使用哪个页面

用户注册后默认待激活，由管理员分配角色；登录后进入对应页面，不提供任意切换身份的演示开关。

| 角色 | 页面 | 主要职责 |
|---|---|---|
| 新人 | `/newbie` | 问答、个人事项、申请确认、入职时间线和本人记忆 |
| Mentor | `/mentor` | 分配新人的带教信号、升级问题处理和知识草稿提交 |
| HR | `/hr` | 入职及问题主题的聚合看板，不开放逐个新人的个人记忆接口 |
| 运营 / 质量 | `/ops` | 运行追踪、评测复核与质量分析 |
| 管理员 | `/admin` | 成员及入职资料、知识生命周期、业务配置 |
| 所有登录用户 | `/workspace` | 按身份展示本人申请、指定审批、反馈和运营统计等 |

权限在服务端执行，不依赖隐藏按钮。管理员可以管理配置、查看工单，但不能代替指定审批人批准申请，也不能直接访问新人的个人记忆接口。禁用账号或变更角色会使原登录会话失效。

## 4. 三个核心使用流程

### 制度更新：先审核，到了生效日再使用

例如，演示制度中的住宿报销上限从 500 元改为 600 元，并在明天生效：

1. 管理员找到原条款，选择「基于此版修改」，填写内容、适用团队、生效日期和变更说明。
2. 保存为草稿。草稿不进入检索，旧版仍可回答。
3. 查看差异和冲突。同领域、同规则主题、适用范围与日期重叠的独立条款会阻止发布；相似问题会提示人工核对。
4. 审核发布后，今天查询仍用旧版，明天查询使用新版；历史日期查询仍能找到当时适用的版本。
5. 恢复旧内容时生成新的草稿，重新审核发布，不删除历史记录。

当前支持粘贴文本及导入 TXT / Markdown 条款，不支持整本 PDF 或 Word 的自动拆分解析。相似条款提示不是完整的语义矛盾识别；同一管理员可以起草并审核，尚未强制双人分权。[完整规则与边界](docs/knowledge-versioning.md)

### 权限申请：用户确认与业务审批是两件事

1. 新人提出申请，Agent 在 IT 领域中生成包含资源、理由、期限及审批信息的确认卡片。
2. **用户确认**后，系统重新校验账号、资源和审批配置，将工单与操作回执一起写入数据库。
3. **指定审批人审批**：在「工单与试用」中批准或驳回；申请人可以取消尚未审批的申请。不得自己审批自己的申请。
4. 重复确认同一个操作只返回同一张工单。网络中断时先查询记录，再使用原请求恢复。
5. 审批通过只表示内置工单已批准，真实权限开通仍需企业 IT 系统执行。

没有配置审批人时会明确提示，不生成虚构姓名，也不声称已经自动分派。管理员补配置后，申请人可取消原待审批申请并重新发起。升级前缺少操作编号的旧确认卡片不能直接执行，应先核查已有工单，再新开会话。

### 人工协作：回答沉淀不绕过知识审核

知识不足的问题可生成升级卡片，由当前分配的 Mentor 处理，并选择是否提交可复用回答；提交后成为知识草稿，只有管理员审核发布后，后续新人才能检索到。Mentor 页面不开放完整聊天记录。

## 5. Agent 如何工作

一次请求先经过登录与会话归属检查、请求回执和前置红线规则，再进入 LangGraph 的意图分类与领域分派。分类器读取近期对话，HR、IT、业务域分别限定可用知识和工具。

- **制度与流程问题**：检索适用的已发布知识，经 BM25 与向量混合排序、来源分级和置信门槛后生成带引用的回答；依据不足时走建议或人工升级路径。
- **个人状态与执行请求**：调用领域允许的工具。只读工具返回查询结果；写工具先暂停，收到用户确认后恢复执行。
- **敏感或越权请求**：由前置规则、工具范围限制与业务权限校验共同约束；不代表已覆盖所有提示注入或绕过方式。
- **执行过程**：记录路由、工具调用、用量与运行状态；对运营展示的工具详情做字段过滤。

HR、IT、业务是三个受控领域子图，不是相互自主协商的 Agent 团队。模型负责理解和生成，账号归属、版本有效期、审批资格与幂等约束由业务代码和数据库执行。

### 上下文、长期记忆与执行状态

短期上下文用于理解“那我的呢”等连续追问；长期记忆保存岗位、团队等稳定信息及提问/路径记录，按本人、Mentor 和 HR 的可见性过滤。程序记忆记录路径结果统计，不会自动训练或更新模型权重。

LangGraph checkpoint 保存“流程执行到哪里、在等待什么确认”，用于暂停恢复。它不等同于聊天记忆，也不能单独保证业务操作只执行一次；本项目另外实现请求回执、数据库互斥锁和工单事务。删除某条可见记忆不等于清除所有消息、checkpoint 和备份，完整的数据留存与删除策略仍需完善。

### 数据从哪里来

知识库使用虚构制度，便于验证来源等级、有效期和冲突处理；用户账号、带教关系、业务状态和工单由使用者注册、配置或实际操作产生。内置社保月份、试用期及年假计算采用演示规则，尚未自动跟随知识版本变化，不作为真实人事依据。

业务适配层有三种配置：`builtin` 使用内置记录，`off` 明确未接入，`live` 尚未实现并会报错。内置实现不是已经连接了真实企业 HR、OA 或 IT 平台。

## 6. 技术选型与取舍

技术栈：Python、FastAPI、LangGraph、SQLAlchemy、MySQL/MariaDB、DeepSeek、DashScope Embedding、BM25；前端采用按角色拆分的 HTML/CSS/JavaScript 页面。LangSmith 是可选追踪集成，当前云端部署未启用。

**为什么保留 LangGraph？** 本项目需要明确的领域路由、写入前暂停和持久化恢复。LangGraph 的状态图与 `interrupt()` 机制适合这条流程，且已与 Python 业务层集成；但恢复可能重新执行节点，因此仍需业务层保证幂等。[官方暂停与恢复说明](https://docs.langchain.com/oss/python/langgraph/interrupts)

**为什么不是 DeepSeek Harness？** Harness 的插件化运行时也是合理候选，能组合模型、工具、会话与存储等能力，并非不能做 B 端流程。当前保留已验证的实现，避免在没有收益证据时重写业务对接；这是项目适配和迁移成本的判断，不是双框架性能实测结论。[Harness 官方介绍](https://www.deepseek.com/harness/)

**为什么使用 MySQL/MariaDB？** 账号、知识、工单和执行状态放在同一类数据库中，便于持久化与备份；云端实际使用 MariaDB 11.4。LangGraph 的 MySQL checkpointer 由项目自行维护，依赖升级需要额外回归，不能忽略这项维护成本。

选型记录是后续补充整理的，不伪装成项目开始前已完成全面对照实验。候选方案、验证清单与重新选型条件见 [ADR-001](docs/adr-001-agent-runtime.md)。

## 7. 验证结果：工程可靠性与答案质量分开看

### 工程验证（2026-09-10）

- **60 项隔离测试通过**：24 项知识版本测试、36 项服务控制测试。覆盖草稿隔离、日期生效、发布冲突、会话越权、角色权限、登录撤销、重复提交、审批限制和反馈权限。在本地及云端镜像中验证，不调用付费模型。
- **真实 MySQL / MariaDB 隔离库验证通过**：并发互斥、锁释放、持久化暂停、重新创建图和 saver 后恢复、同一操作只生成一张工单。不是整机断电或网络分区演练。
- **前端静态检查通过**：46 个调用点与 48 个后端接口匹配，8 段页面脚本可以解析；另检查了旧确认卡片阻断及离开待确认操作的前端状态逻辑。不是完整浏览器端到端覆盖。
- **发布验证通过**：公网登录与就绪检查、未登录访问拒绝、应用数据库专用账号、备份隔离恢复；既有账号与业务记录保留，26 个原有评测及人工审核文件逐字节核对一致。

测试源码见[知识版本测试](tests/test_knowledge_versions.py)、[服务控制测试](tests/test_service_controls.py)，自动检查配置见 [GitHub Actions](.github/workflows/checks.yml)。

### 模型质量：历史结果，不当作本次发布成绩

最近一次本地留存的全量模型运行时间为 **2026-09-05 23:43:24**，结果 **58/60**：事实 21/21、跨系统 12/12、流程 12/12、建议 7/9、拒答 6/6。整套题记录费用约 ¥0.2187，耗时 488.4 秒，外部系统模式固定为 `off`。

上述汇总核对自本地归档 `report_20260905_234324.json`；该逐题文件未随本次文档公开。仓库中的[历史报告](ramp/eval/reports/)保留其他运行记录，包括不同版本的 60/60，不能将其视作当前代码的验证结果。本次功能升级与 README 更新都没有重新运行付费模型黄金集。

黄金集由作者依据演示知识构造，不是真实用户样本；6 道拒答题通过不足以证明线上拒答率达到 98%。工程测试的 60 项通过也不等于 60 道模型题全部答对。历史费用下降受缓存、配置和版本变化影响，不包装为严格对照实验的降本结论。

## 8. 本地运行与首次体验

### 环境与初始化

准备 Python 3.11+、uv 和可连接的 MySQL/MariaDB。Node.js 仅用于前端脚本检查，不是应用启动的必需条件。

```sh
git clone https://github.com/sunjiale1119/ramp-onboarding-agent.git
cd ramp-onboarding-agent
cp .env.example .env
uv sync --frozen
```

在项目 `.env` 中填入数据库和模型配置。以下为配置项示例，尖括号内容必须自行替换，密钥不得提交到 Git：

```dotenv
MYSQL_HOST=127.0.0.1
MYSQL_PORT=3306
MYSQL_USER=<具备本库建表和读写权限的账号>
MYSQL_PASSWORD=<数据库密码>
MYSQL_DB=ramp

DEEPSEEK_API_KEY=<自己的DeepSeek密钥>
DASHSCOPE_API_KEY=<自己的DashScope密钥>
RAMP_EMBEDDING_BACKEND=dashscope
RAMP_EMBEDDING_MODEL=text-embedding-v4
RAMP_EMBEDDING_DIM=1024

RAMP_ADMIN_USER=admin
RAMP_ADMIN_PASSWORD=<首次初始化使用的强密码>
RAMP_EXTERNAL_MODE=builtin
RAMP_ALLOW_DEMO_LOAD=0
```

```sh
uv run python -m ramp.bootstrap
uv run uvicorn ramp.api:app --host 127.0.0.1 --port 8000
```

打开[本地登录页](http://127.0.0.1:8000/login)。初始化只创建管理员并装载演示知识，不自动创建普通成员。真实向量初始化及模型问答会产生 API 费用；`hashing` 可用于离线开发，但不是等价的真实向量检索质量验证。

管理员配置实际使用 `RAMP_ADMIN_USER` 和 `RAMP_ADMIN_PASSWORD`。未配置时默认 `admin / ramp2026`，仅适合隔离演示。修改这些变量不会覆盖已经存在的管理员密码；初始化日志可能包含管理员凭据，请勿公开分享。

### 首次体验建议

1. 分别注册新人、Mentor、审批人账号，由管理员在「成员」中激活并设置角色。审批人可以是现有合法角色的独立账号。
2. 在同一成员设置中填写新人的团队、岗位、入职日期、领域和 Mentor，不需要再创建一份独立员工档案。
3. 空环境先通过管理员配置接口建立资源目录和岗位映射（见下文），再在「外部系统」中维护已有岗位的权限和实际审批账号。需查询的社保、公积金或材料状态也应先录入；没录入就应得到“查不到”，不是演示失败。
4. 新人尝试制度问答与追问、权限申请；切换到指定审批账号，在「工单与试用」处理申请。随后尝试知识草稿、差异审核和按日期预览。
5. 提交真实试用反馈，由运营填写处理结果。未试用前不生成满意度或完成率。

一键演示装载仅在独立测试环境显式设置 `RAMP_ALLOW_DEMO_LOAD=1` 后开放，会创建共享密码演示账号；正常团队试用不应开启，也不要在真实数据上运行装载或清空脚本。

### 空环境的目录配置

当前后台可以修改已有岗位的权限与资源审批人，但**尚无新增资源目录和岗位行的完整界面**，首次配置需使用管理员接口。管理员在自己的本地系统登录后，可进入 `/docs`，依次向 `POST /api/admin/external/config` 提交以下两个 JSON 请求，建立一个内置 VPN 示例资源及默认岗位映射：

```json
{"key":"entitlement_catalog","value":{"vpn":"VPN"}}
```

```json
{"key":"role_entitlements","value":{"*":["vpn"]}}
```

随后返回「外部系统」为 VPN 选择实际审批账号。上述接口会替换指定配置项的整份内容：仅对空环境直接使用示例；已有环境先读取 `GET /api/admin/external` 并保留原条目，不要覆盖他人配置。这里创建的是本项目的资源记录，不会真的创建企业 VPN 权限。

## 9. 测试、部署与运维

不调用付费模型的基础检查：

```sh
uv run python -m unittest discover -s tests -v
uv run python scripts/check_web.py
```

验证真实数据库锁与恢复时，可由运维人员运行 `uv run python -m scripts.verify_mysql_controls`。它需要建库/删库权限，仅操作自行生成的隔离测试库并在结束后清理，不应为此提升线上应用账号的全局权限。

重新验证模型答案质量时，单独运行 `uv run python -m ramp.eval.run`，会调用模型并产生费用。`reset`、`wipe`、`scripts/check_external.py` 等清理或演示检查工具不得在真实业务数据库随意运行。

部署采用单机 Docker Compose，应用与 MariaDB 分离，依赖版本从 `uv.lock` 导出到 `deploy/requirements.txt`。当前已有应用健康检查、日志轮转、数据库专用账号、问答日限额与并发限制；默认每账号每天 50 次问答、最多 3 个执行，不是精确人民币预算。

- `/health/live`：进程存活检查。
- `/health/ready`：数据库及必要迁移就绪检查，不调用付费模型。
- `/workspace`：按角色查看请求、工单、反馈、运维统计和审计。

升级已有数据库必须先备份，再运行 `python -m ramp.migrate_knowledge`；不得为了升级重置账号。知识版本上线后不能直接退回不理解版本过滤的旧程序。备份、隔离恢复、发布版本固定和上线核对步骤见[运维手册](docs/operations.md)。

## 10. 距离正式企业上线还缺什么

当前适合以演示制度和非敏感试用身份验证业务流程，不适合直接接管企业真实员工服务。主要缺口包括：

- HTTPS、可信反向代理、企业 SSO/MFA 和默认凭据治理。
- 真实 HR / 工单 / 权限 API 的接入、下游幂等与状态对账。
- 制度版本与业务计算规则的统一治理、双人审核及更完整的语义冲突检查。
- 宿主操作系统更新、独立安全审查、隐私留存和删除策略。
- 异地加密备份、自动告警、高可用及并发压力测试。
- 真实团队试用、人工质量抽查和可复核的产品效果数据。

已有工程措施不是安全认证，也不能用“采用了 Agent 框架”替代企业验收。建议的 5–10 人、7 天试用方案目前只是计划，详见[企业就绪评估](docs/enterprise-readiness.md)。
