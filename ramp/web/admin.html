管理员能做什么 / 不能做什么 能：激活账号、分配角色、绑定员工档案、重置密码、删除账号。
不能：看新人的提问原文。管理员权限管的是"账号和配置"，不是"绕过可见性矩阵"—— 这两件事经常被混为一谈，很多系统里 admin 等于上帝。
你现在的 views 是 ，里面没有 newbie。 直接开新人的 memory 接口，服务端照样 403。

改角色 / 改 employee_id 后要点「保存」才生效。 停用会同时踢掉该账号的在线会话，不是等它自然过期——否则停用只是个摆设。

新增条目
保存会做两件事 写库 + 立刻重算这条的向量并重建索引。
少了第二步，管理员改完在前台搜不到，会以为没生效—— 而实际上库里已经改了，只是检索还在用旧索引。这种"改了但看不见"最难查。
L3 是干什么用的 L3 打了 0.75 的乘法上限，结构上过不了 0.62 的作答阈值—— 录进去不是为了让它直接回答，是为了让它能被检索到、然后触发升级。 过期条目同理。
档案和账号是两件事 账号回答"你是谁、能进哪个页面"；档案回答"你哪天入职、谁带你、在哪个组"。
新人注册后需要两步：在「用户与授权」里激活并派角色，再在这里建一份档案并绑定—— 没有档案，新人工作台打不开，30 天时间线和主动推送都无从谈起。
新建档案
保存时顺带做的事 写入三条语义记忆（岗位 / Mentor / 入职日期）。新人工作台右栏那个 「Ramp 记得关于我的」读的就是这三条 —— 不写的话新人第一次打开看到的是空的。
bootstrap 灌种子时做了这件事，手工建档案也必须做，否则两条路径产出的数据不一致。
